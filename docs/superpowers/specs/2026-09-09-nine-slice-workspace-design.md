# 九宫格候选与预览工作区设计

日期：2026-09-09

## 目标

让 UI 美术可以在 UI2HTML 工程内，用本地算法发现适合九宫格的资源，确认同源图片组和四个边距，并在预览中快速对比原图与九宫格效果。PSD 不参与这一步，九宫格数据属于独立的 `.ui.json` 工程。

## 已确认的交互

- 工作区顺序为：层级 / 资源绑定 / 九宫格 / 预览 / 导出。
- 用户进入“九宫格”页签后，主动点击“扫描/更新候选”；打开、保存工程不会自动扫描。
- 算法只推荐，不直接修改。候选可“确认”或“跳过”；跳过结果会被记住，可通过恢复入口重新纳入候选。
- 用户可以从工程资源中多选未被推荐的图片，并明确将它们作为同一逻辑图片组处理。
- 候选和手动补选都使用现有四条边距线进行视觉确认；算法仅预填建议边距，用户可拖线或输入数值调整。
- 确认后立即在当前工程中应用；保存工程时持久化结果。
- “预览”页签统一提供设备预览、安全区/设备外壳和整张画布的“原图 / 九宫格图”切换，默认显示原图，切换状态随工程保存。

## 算法边界

候选检测采用本地、保守规则，优先推荐矩形面板、边框和按钮底图等具有稳定边缘与可拉伸中心的图片。小图标、角色图和复杂装饰图默认不推荐，但必须可以手动添加。

同源归组先去除透明边缘，再将图片统一缩放后比较视觉内容；文件名只作辅助，不能作为主要依据。算法输出候选组、置信度和建议理由，由用户确认归组。

## 数据模型

九宫格处理以逻辑图片组为单位。一个组至少包含：

- 原始成员图片路径列表；
- 最高分辨率成员作为公共源图；
- `.assets/9` 中的公共源图副本路径；
- `left/top/right/bottom` 四个边距；
- `suggested/confirmed/skipped` 状态；
- 候选置信度和建议理由。

原图永远保留。`.assets/9` 的副本用于工程内独立管理和对比；九宫格不是提前生成固定尺寸的拉伸图片，而是公共源图配合四个边距在渲染时完成。

节点通过逻辑图片组引用九宫格源图。原图/九宫格切换只改变预览使用的渲染源，不改变节点的位置、尺寸和原始资源。

## 重新扫描与错误处理

- 重新扫描不得覆盖已确认的边距、公共源图或已跳过决定。
- 同组成员发生变化时，显示差异并要求用户重新确认，不静默改变已确认组。
- 无法生成有效边距、图片全透明、图片过小或公共源图缺失时，保留原图并显示明确警告。
- 工程保存失败时不产生不完整的 `.ui.json`；生成的九宫格资源与工程数据保持同一保存事务语义。
- 当前阶段不生成最终自研引擎 JSON 的九宫格字段；后续适配层读取本设计保存的源图和边距。

## 验收标准

1. 手动扫描后，明显适合九宫格的资源出现在候选列表，普通图标不会大量进入候选。
2. 用户可以确认、跳过、恢复跳过项，以及手动多选图片建立同一逻辑图片组。
3. 确认后能够使用四条边距线修改建议，并立即在当前工程预览中看到九宫格结果。
4. 同源不同尺寸图片使用最大分辨率图片作为公共源图，原图仍完整保留。
5. 保存并重新打开工程后，逻辑图片组、四个边距、`.assets/9` 资源和跳过/确认状态均恢复。
6. 预览页签可整体切换原图与九宫格图，并与设备比例、安全区和设备外壳预览同时工作。
