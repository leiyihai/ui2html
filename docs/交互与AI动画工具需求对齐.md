## 1. 产品定位

UI2HTML 的核心不是制作一个完整的游戏运行时，也不是让用户手动编写每个控件的事件逻辑，而是：

> 将 PSD 素材和 UI 设计，快速整理为可预览、可沟通、可生成动画、可导出到其他游戏引擎的 UI 数据。

因此，交互数据的主要用途是：

1. 在工具内模拟高保真交互效果。
2. 为 AI 动画生成提供明确的控件状态和视觉上下文。
3. 让 AI 生成的动画能够反向拆分为时间轴和关键帧。
4. 为目标游戏引擎导出可映射的交互和动画数据。

它不负责替代目标游戏引擎中的完整业务逻辑、网络逻辑或 Lua/C#/C++ 代码。

## 2. 默认推荐的总体方案

### A01：交互字段的定位

**默认推荐：把交互字段定义为“跨引擎交互语义和状态描述”，而不是完整运行时事件系统。**

它描述的是：

- 控件支持哪些状态。
- 哪些操作可以被预览器模拟。
- 哪些状态可以触发动画。
- 使用什么视觉反馈模板。

它不直接保存目标引擎的业务回调代码。

### A02：是否需要用户手动填写交互语义

**默认推荐：不要求用户填写。**

系统根据控件类型、层级、资源槽位、节点名称和图片状态自动生成基础交互描述；AI 根据当前工程和 HTML 再补充缺失信息。

用户只在自动判断不合适时进行修改，修改属于例外操作，不是标准流程。

### A03：属性面板中的交互区域

**默认推荐：按控件类型条件显示，不对所有节点展示完整交互面板。**

- Button、CheckBox、RadioButton：显示完整交互状态和视觉模板。
- Slider：显示拖拽和值变化相关配置。
- Edit：显示聚焦、输入和提交相关配置。
- List/GridView：显示项目选中、点击和滚动相关配置。
- ProgressBar：默认只作为状态显示，不默认接受用户操作。
- Layout、StaticImage、StaticText：默认不显示交互配置。

如果普通图片或 Layout 需要可点击，再主动添加“交互区域”，不改变它原本的控件类型。

### A04：交互视觉模板与事件动作分离

**默认推荐：分为两个概念。**

- 交互视觉模板：缩放、透明度、颜色、描边、发光、波纹等视觉反馈。
- 事件/动画触发描述：点击、悬停、拖动、选中、提交等语义触发点。

第一阶段优先实现视觉模板和动画触发描述；不在属性面板里编辑目标引擎代码。

### A05：状态资源不足时自动补全

**默认推荐：系统自动补齐缺失状态，优先保证效果可用。**

资源状态的优先级：

1. 美术明确提供的状态图片。
2. 同组资源或相关状态图片推导。
3. 程序滤镜和变换生成。
4. 通用交互特效生成。

例如按钮只有一张图片时，系统仍然自动生成悬停、按下、禁用、聚焦和点击反馈。

## 3. 自动状态补全规则

### A06：单图按钮的默认补全

当按钮只有一张图片时，默认使用以下效果：

| 状态 | 默认效果 |
|---|---|
| 普通 | 使用原图 |
| 悬停 | 轻微提亮，必要时增加弱发光 |
| 按下 | 轻微压暗，缩放到约 95%，可附加短暂位移 |
| 禁用 | 降低透明度和饱和度 |
| 聚焦 | 增加描边或焦点光圈 |
| 点击 | 播放短暂缩放、闪光或波纹 |

效果强度由系统根据图片主色、明暗和界面风格自动调整。

### A07：其他控件的默认补全

- CheckBox/RadioButton：颜色叠加、勾选标记、选中发光或缩放。
- Slider：自动绘制轨道、填充区域和滑块头。
- ProgressBar：根据进度和尺寸自动绘制填充区域。
- Edit：自动显示聚焦边框、输入光标和占位提示。
- List/GridView：自动生成悬停背景、选中背景和点击反馈。

如果美术提供了完整状态资源，则优先使用资源，不再叠加过强的程序效果。

### A08：生成状态的来源记录

**默认推荐：内部记录状态来源，但不要求用户维护。**

每个视觉状态可以标记为：

- 美术资源。
- 由其他资源推导。
- 程序滤镜生成。
- 程序动画生成。
- AI 生成。

这样导出时可以决定是导出图片、颜色/透明度/缩放参数，还是导出动画数据。

## 4. AI 动画工具的工作方式

### A09：HTML 的定位

**默认推荐：HTML 是工具内部的动画分析中间表示，用户不需要手动导出和导入。**

UI2HTML 在后台根据当前工程生成完整 HTML 和场景元数据，交给 AI 使用；用户只看到 AI 面板和结果。

HTML 中需要带有不可见的识别信息：

- 稳定节点 ID。
- 控件类型。
- 父子层级。
- 图片和文字资源引用。
- 视觉尺寸和交互尺寸。
- 可用状态和状态来源。

### A10：AI 是否要求用户先选择参与动画的节点

**默认推荐：不要求。**

AI 默认分析完整界面，自行判断哪些节点参与动画。

用户仍然可以通过一句话限制范围，例如：

> 只修改抽奖按钮和奖品区域，不要修改标题和背景。

选择节点属于可选的约束手段，不是动画制作的前置步骤。

### A11：AI 的输入方式

**默认推荐：集成式对话面板，支持自然语言和预设任务。**

用户可以输入：

- 制作入场动画。
- 优化当前按钮点击反馈。
- 制作抽奖流程。
- 让弹窗打开时更有弹性。
- 保持布局不变，只调整动画节奏。

也可以直接选择“入场动画”“按钮反馈”“抽奖流程”等预设，不要求用户自己写专业动画描述。

### A12：AI 生成结果的处理方式

**默认推荐：先生成临时版本，审查后应用。**

AI 生成后应立即在当前工具内预览，并显示：

- 影响了哪些节点。
- 新增了哪些动画片段。
- 修改了哪些关键帧。
- 是否使用了自动补全的交互效果。
- 是否存在无法映射或需要人工确认的部分。

用户可以选择：

- 应用结果。
- 继续对话修改。
- 只应用部分结果。
- 放弃本次结果。

AI 默认不能直接覆盖 UI 层级、控件类型和资源绑定；除非用户明确授权。

## 5. 动画数据和反向转换

### A13：AI 输出格式

**默认推荐：AI 输出结构化动画数据，不直接输出无法解析的 CSS 或脚本。**

动画数据至少应包含：

- 节点稳定 ID。
- 动画片段名称。
- 属性轨道。
- 时间和关键帧。
- 缓动和插值方式。
- 循环、延迟、播放方向。
- 交互触发条件。

这样可以把 AI 结果反向拆回普通时间轴，继续手动编辑和导出。

### A14：手动 K 动画

**默认推荐：完整保留手动动画能力。**

AI 生成的动画进入普通动画时间轴后，用户可以：

- 拖动、复制、删除关键帧。
- 修改时长和缓动曲线。
- 只重新生成局部节点。
- 锁定不希望 AI 修改的节点。
- 将 AI 动画和手动动画混合使用。

AI 负责提高起点，时间轴负责最终精修。

### A15：AI 生成动画的作用范围

**默认推荐：AI 只修改动画和交互表现，不默认修改结构。**

默认允许修改：

- 位置、缩放、旋转、透明度。
- 视觉尺寸。
- 交互反馈效果。
- 动画片段和关键帧。

默认不允许修改：

- UI 层级。
- 控件类型。
- 资源绑定关系。
- PSD 来源关系。
- 工程分辨率。

如果 AI 发现结构问题，应先提示用户，而不是直接修正。

## 6. 用户最终需要做什么

### 必须做

1. 导入 PSD 或已有素材。
2. 在 UI 编辑器中整理层级。
3. 指定控件类型。
4. 绑定图片和文字资源。
5. 调整视觉尺寸和交互尺寸。
6. 检查 AI 生成的动画和交互效果。
7. 确认后导出。

### 不需要做

- 不需要手动填写完整交互语义。
- 不需要手动补齐每个控件状态。
- 不需要手动选择所有动画节点。
- 不需要先手写动画关键帧。
- 不需要手动导出 HTML 再交给外部 AI。
- 不需要编写目标引擎的交互代码。

### 可选做

- 用自然语言限制 AI 的修改范围。
- 手动调整 AI 生成的关键帧。
- 手动补充特殊动画。
- 修改自动生成的视觉效果强度。

## 7. 推荐实施顺序

### 第一阶段：基础数据和预览

- 明确交互状态名称。
- 为 HTML 和工程数据加入稳定节点 ID。
- 实现单图控件的自动状态补全。
- 让预览器能够模拟悬停、按下、选中、拖动和输入。

### 第二阶段：内置 AI 动画入口

- 在软件内加入 AI 对话面板。
- 自动读取当前工程和内部 HTML。
- 支持自然语言生成动画。
- 先生成临时版本并预览。

### 第三阶段：动画反向导入和时间轴编辑

- 将 AI 结果转换为关键帧。
- 支持动画片段、轨道和缓动编辑。
- 支持局部重新生成。
- 支持撤销、对比和审查后应用。

### 第四阶段：导出适配

- 将通用动画数据映射到自研引擎。
- 对其他引擎保留适配扩展位。
- 无法导出的效果生成警告，并尽量保留网页预览效果。

## 8. 暂时不影响大方向的细节

以下内容先不作为本轮决策阻塞项：

- AI 面板放在左侧、右侧还是独立工具区域。
- 是否支持语音输入。
- 默认动画预设的具体名称。
- 发光、波纹、粒子等效果的具体参数范围。
- AI 服务使用本地模型还是远程模型。
- 多个 AI 任务是否排队执行。
- 时间轴是否支持多选关键帧快捷键。
- 各目标游戏引擎的具体事件字段名称。
- AI 结果是否允许导出为独立动画文件。

这些问题在主流程跑通后再处理，不影响当前总体架构。

### 当前主流程

```text
PSD/素材导入
  → UI 编辑器整理层级、控件类型和资源
  → 系统自动生成基础交互状态与兜底效果
  → 用户在 UI2HTML 内发起 AI 动画任务
  → AI 同时读取工程数据和效果图
  → AI 调用已适配的特效能力生成结构化动画
  → 临时预览、差异审查、版本记录
  → 用户确认后写入动画时间轴和派生资源
  → 手动 K 动画精修
  → 分离导出 UI JSON、动画/流程文件和所需资源
```
