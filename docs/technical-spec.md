# PSD 导入与自研引擎 UI 工程技术规格

状态：PSD 转换器闭环版本（2026-09-09 讨论冻结基线）

> 本文顶部的“冻结基线”优先于后文早期讨论记录。后文保留历史背景，若出现冲突，以本节为准。

## 冻结基线（2026-09-09）

### 产品定位

UI Editor 是“PSD 一次性导入与自研引擎 JSON 转换工具”，不是完整的运行时 UI 布局设计器。PSD 只提供初始画布、图层、素材和视觉位置；导入完成后工程与 PSD 解耦，PSD 的后续修改不会同步或影响已有工程。

### 导入闭环

每次导入 PSD 都创建新的独立工程。导入流程由 UI Editor 的入口启动后台导入任务：解析 PSD、裁切和复制资源、本地判断控件类型、批量调用本机 Codex CLI 生成节点后缀和图片名、校验并写入完整工程。资源槽位不在导入阶段自动绑定，导入完成后由资源绑定工作区处理。任务期间显示等待动画和阶段文案，禁止编辑器操作；允许取消，取消后删除临时目录且不影响当前工程。

Codex CLI 是第一版唯一 AI 接入方式，不保存 API Key 或账号信息。AI 每个 PSD 尽量只调用一次，使用画布预览、图层树和唯一图片联系表作为输入，并将结果缓存。CLI 不可用、超额或失败时仍完成导入，使用本地备用名称，并保留可重新命名入口。

### 命名与稳定引用

AI 只返回英文语义后缀和图片语义名；本地程序添加控件缩写、`img_` 前缀、编号并执行合法性校验。节点名称形如 `slider_volume`，图片资源名称形如 `img_volume_fill`。节点名称来源记录为 `ai`、`fallback` 或 `manual`；F2 修改后的 `manual` 名称不可被 AI 覆盖。

节点内部 ID 与显示名称分离并保持稳定；资源以独立资源 ID 或内容哈希引用。重命名不影响父子关系、图片绑定或最终导出。

### 类型、槽位与预览

PSD 中明确的中文控件类型文件夹优先，转换为对应英文控件类型；根节点普通文件夹默认转换为空 `Layout`。AI 不覆盖明确的类型判断。控件资源不在导入、打开或类型转换时自动绑定，统一通过资源绑定工作区或 `Ctrl+B` 手动确认。

只有经过 Codex 分析但置信度不足的待确认节点所在层级自动展开并显示红色底色；被选中时红色进一步变亮。Codex 不可用时的本地兜底命名是可继续编辑/导出的正常结果，只显示底部汇总提示，不把整棵层级树标红。预览不自动检测遮挡，也不因遮挡自动修改节点，只提供 CSS 设备外观模拟和用户主动检查。

预览方向根据 PSD 画布宽高自动判断：宽大于高为横屏，高大于宽为竖屏，相等为方形。设备 Tab 同时包含比例和外观预设：桌面 `16:9`、平板 `4:3`、水滴 `20:9`、药丸 `19.5:9`、超宽 `21:9`，并支持横竖屏对应比例。CSS 仅模拟刘海、药丸、水滴、圆角、系统区域和底部小白条，不写入工程或最终 JSON。预览支持缩放、平移、居中，并可点击元素跳转到 UI Editor 节点。

### 工程文件与导出

`.ui.json` 是编辑器工程事实来源，`.assets` 保存独立图片，`.analysis.json` 保存 AI 置信度、候选名和待确认记录，`.engine.json` 是当前自研引擎最终 JSON。工程不保存 PSD 实时依赖；PSD 路径和图层 ID不作为重新挂载依据。

### 工具与文件术语规范

为避免混淆，沟通和界面文案统一使用以下名称：

- **引擎 UIEditor**：自研引擎附带的原生 UI 编辑器，路径为 `engine-core\res\client\tools\UIEditor.exe`，用于打开和检查最终引擎 JSON。
- **UI2HTML 编辑器**：本项目正在开发的网页 UI 编辑器，位于 `ui-editor`，用于打开和编辑 `.ui.json` 工程。
- **引擎 JSON**：自研引擎的原生 UI JSON，交给“引擎 UIEditor”打开。
- **UI2HTML 工程**：以 `.ui.json` 结尾的工程文件，交给“UI2HTML 编辑器”打开。

如果用户没有明确使用上述固定术语，或只说“UI 编辑器”“JSON”“打开”等无法判断目标时，必须先询问用户指的是“引擎 UIEditor”还是“UI2HTML 编辑器”，以及对应的“引擎 JSON”还是“UI2HTML 工程”，确认后再继续操作。

导出前校验节点类型、必填字段、资源引用、槽位和名称。错误阻止导出，警告允许继续。第一版支持当前自研引擎导出；九宫格完成 UI2HTML 编辑器内的候选、确认、资源保存、显示切换，并在引擎 JSON 导出时映射为九宫格源图、`StretchType=NineGrid` 和 `StretchOffset`；动画和完整响应式适配布局暂不进入本次闭环。

### 验收重点

- PSD 导入、AI 命名、本地资源整理、工程保存、预览、人工校正和自研引擎 JSON 导出可以完整走通。
- 导入任务可取消且不会污染当前工程或留下半成品。
- 没有 Codex CLI 时仍能完成导入和保存。
- 修改 PSD 后重新打开已有工程，工程内容保持不变。
- AI 重跑不会覆盖手动命名；稳定 ID 保证绑定不丢失。
- 导入、保存、重开、导出后的节点层级、位置、类型、绑定和资源引用一致。

## Problem Statement

当前 UI Editor 过度依赖 PSD 文件作为持续数据源。用户在 PSD 中修改图层后，可能导致编辑器中的图片位置、控件类型、层级和属性异常变化；编辑器保存的结果也不能稳定恢复。PSD 的职责应当只是提供初始素材、尺寸、位置和初始层级，不能继续影响已经保存的 UI 工程。

编辑器还需要把 PSD 图层整理为自研引擎 UI 控件，支持层级操作、控件类型转换、资源槽位绑定、独立素材管理、工程保存和最终导出，并且让这些数据有清晰的归属、稳定的保存格式和可验证的导入行为。

## Solution

将 `.ui.json` 定义为 UI Editor 的工程文件和唯一事实来源，将与其同名的 `.assets` 目录定义为工程独立资源目录。

PSD 仅作为一次性或追加式导入源：导入时读取图层、文件夹、文字、可见性、透明度、位置、尺寸、旋转和视觉效果，并把结果复制、转换到当前工程。导入完成后，工程不保存 PSD 依赖，也不监听或自动同步 PSD 的后续增删改。

用户可以通过文件菜单或拖拽导入 PSD、PSD 中选中的图层和外部图片；PSD 文件夹转换为 `Layout`，图片转换为图片资源和 UI 节点，文字转换为可编辑文字节点，复杂视觉效果转换为独立 PNG。之后所有层级、控件类型、绑定、名称和少量视觉校正操作均直接作用于 `.ui.json` 工程。

最终导出时，由工程数据生成自研引擎 JSON；工程内部继续保存 `.assets` 独立 PNG，导出测试包时再生成引擎兼容的 imageset。九宫格在 UI2HTML 编辑器内完成候选、确认、保存和预览，并在导出时使用 `.assets/9` 的源图和引擎九宫格字段。

## Implementation Decisions

### 1. 工程边界与事实来源

- `.ui.json` 是 UI Editor 工程文件的唯一事实来源，保存完整场景快照。
- `.assets` 是与 `.ui.json` 同名的工程资源目录，默认位于工程文件旁边。
- PSD 是只读导入源。工程不保存 PSD 来源路径、PSD 图层 ID 或自动更新信息；PSD 后续修改、增删、重命名和移动不会改变已有工程。
- 工程数据不得依赖 `psd-layer:<layerId>` 重新从 PSD 挂载图片。图片必须复制到 `.assets`，JSON 只引用工程内资源的相对路径。
- `.ui.json` 保存设计画布尺寸、节点顺序、父子关系、名称、可见性、锁定状态、当前最终位置、当前最终尺寸、旋转、控件类型、控件属性和资源槽位；位置与尺寸不再拆成 PSD 原始值和校正值两套数据。预览视口、缩放模式和安全区可以作为查看偏好保存，但不参与节点布局数据。
- `ProgressBar` 和 `Slider` 使用可选的进度配置保存 `value`、`direction` 和 `reverse`；`value` 始终限制在 `0..1` 并按两位小数精度保存。旧工程没有该配置时按值 `0`、根据宽高推断方向、`reverse=false` 处理。
- 撤销/重做记录属于当前编辑会话，不写入 `.ui.json`；重新打开工程不恢复历史记录。
- 最终引擎 JSON 通过独立适配层由工程数据生成，编辑器内部字段不直接等同于引擎字段；当前版本不实现完整响应式布局编辑器和动画，但支持明确配置的相对宽高，并由适配层转换为引擎 `Area`。
- `ccc.json` 和 `res/layout` 样例作为引擎字段、布局和底图表达的参考；无法映射的专有字段必须保留扩展数据或提示，不得静默丢失。

### 1.1 九宫格资源处理设计（2026-09-09）

- 九宫格处理单位是“逻辑图片组”，不是单个节点。多个节点使用同一图片，或多张内容相同但尺寸不同的图片，经用户确认后可以共用一份九宫格源图。
- 九宫格工作区分为三个小页签：`候选图片`、`原图标记`、`九宫格结果`。九宫格工作区不显示层级面板、属性面板或场景总览。
- `候选图片`列出工程中的全部图片，包括普通图片节点和已绑定到控件资源槽位的图片；用户可以多选图片并确认组成逻辑图片组，也可以跳过算法候选或手动补选。
- 本地算法只做保守推荐，不直接修改节点。候选识别优先针对矩形面板、边框、按钮底图等具有稳定边缘和可拉伸中心的资源；小图标、角色图和复杂装饰图不主动推荐，但可以手动补选。
- 同源图片组通过去除透明边缘、统一缩放后的视觉内容相似度判断，文件名只作辅助信息。算法给出候选组和置信度，用户确认后才建立归组。
- 用户可以在九宫格工作区多选未被推荐的图片，明确将它们作为同一逻辑图片组处理。
- `原图标记`对已确认的图片组显示公共源图。用户通过四条可拖动边界线标记固定区域和可拉伸区域，点击“转换”后生成九宫格小图；四条边距值以源图像素保存。普通低变化区域可以压缩为约 1 像素，渐变或纹理变化较大的可拉伸区域保留约 25% 的原区域，避免渐变被过度压扁；四角和固定边缘保持不变。
- 逻辑图片组中选择分辨率最高、像素尺寸最大的原图作为公共九宫格源图；原始图片全部保留，不修改、不删除。`.assets/9` 中保存公共源图的独立副本和生成结果。
- 场景级氛围背景单独处理：只识别 PSD 根层级中最底部且覆盖画布大部分区域的图片；面板底图、按钮底图、进度条底图等控件资源不属于此规则。保存 UI2HTML 工程时保留原图，生成引擎测试包时才额外生成 50% 像素尺寸的背景资源，以降低图集占用。
- 用户确认候选组后进入 `原图标记`；用户取消候选时记录为“已跳过”，重新扫描不再次推荐，另有“恢复已跳过候选”入口。
- `九宫格结果`只列出已经生成的九宫格小图、来源图片和当前四个边距，供用户查看和在预览中使用；不要求用户再次确认或重新填写边距。结果页的边距始终沿用 `原图标记` 阶段的值；需要修改时必须返回第二阶段重新标记并重新转换。
- 九宫格组、成员原图路径、公共源图路径、生成结果路径、四个边距、候选置信度、确认/跳过状态和工程预览切换状态写入 `.ui.json`；九宫格图片写入工程 `.assets/9`。不使用浏览器 `localStorage` 作为工程数据来源。
- 工作区顺序固定为“层级 / 资源绑定 / 九宫格 / 预览 / 导出”。设备比例、安全区、设备外壳和原图/九宫格整体切换只出现在“预览”工作区；普通属性面板不增加九宫格编辑项。
- 预览默认使用原图；用户切换后，整张画布统一使用已确认的九宫格源图和边距渲染。切换状态保存到 `.ui.json`，只改变检查显示，不改变节点位置、尺寸或原图资源。
- 扫描由用户在九宫格工作区点击“扫描/更新候选”触发。重新扫描必须保留已确认和已跳过的决定，不覆盖已经确认的边距或公共源图。
- 当前阶段实现 UI2HTML 编辑器内的候选、确认、三阶段标记与转换、资源保存、工程重开恢复和原图/九宫格显示切换；自研引擎 JSON 导出使用已生成的 `.assets/9` 图片、`StretchType=NineGrid` 和 `StretchOffset`，通用图片已支持导出为临时 imageset。

### 2. 工程生命周期与保存

- 文件菜单提供：新建、打开、保存、另存为、PSD 中选中导入、一键导入 PSD、导入图片、清理未使用资源、关闭工程。
- 打开 `.ui.json` 时恢复工程快照，不读取同名 PSD，不创建或覆盖旧的同名普通 JSON。
- 同一个 `.ui.json` 已打开时切换到已有标签页，不创建重复标签页。
- 每个工程标签页独立拥有场景、选择状态、预览设置和脏状态；切换标签页不重新从磁盘加载。
- Ctrl+S 打开快捷操作面板，不直接执行保存。面板左侧显示“新建”“打开工程”“导入 PSD”“导入图片”，右侧显示“保存”“另存为”。
- 快捷操作面板沿用 `T` 类型菜单的唤起和关闭交互；用户点击选项后执行对应操作，按 `Esc` 或点击面板外部区域关闭且不执行操作。
- 快捷操作面板中的“保存”保存当前工程；没有保存路径的临时工程进入“另存为”流程。“另存为”创建新的 `.ui.json` 和匹配 `.assets`，复制全部工程资源并更新引用，之后与原工程完全独立。
- 首次保存允许选择任意文件系统位置；工程文件强制补全 `.ui.json` 扩展名并创建 `.assets`。
- 另存为目标已存在时先提示覆盖，并在覆盖前创建带时间戳的备份。
- 保存使用临时目录生成完整工程，再一次性替换正式内容；失败时保留旧工程、旧资源和备份，不留下不完整结果。
- 外部修改 `.ui.json` 后保存应提示覆盖、重新加载或取消。
- 最后一个工程标签页关闭后显示欢迎页，提供新建、打开、导入 PSD 和导入图片入口。
- Alt+W 关闭当前工程标签页；脏工程显示保存、放弃、取消选项。关闭不会修改 PSD 或原始外部图片。浏览器保留 Ctrl+W 用于关闭网页页签。
- 右下角的操作状态提示显示 4 秒后自动消失；出现新提示时重新计时，常驻警告不受此计时影响。

### 3. PSD 导入

- “一键导入 PSD”直接导入所有图层和文件夹，包括隐藏图层和空文件夹，并保留隐藏状态。
- “PSD 中选中导入”先打开分阶段选择器；只有点击“导入”后才提交节点和资源，取消不修改工程和 `.assets`。
- PSD 选择器按 Photoshop 图层树展示缩略图、文件夹/图层图标、名称、可见性、类型和像素尺寸，并支持展开折叠。
- 选择器默认全部不选。选中文件夹时默认勾选全部后代；用户可以展开后取消子项。
- 选择器和 UI 层级树统一使用选择规则：普通点击单选并清除其他选择；Ctrl/⌘ 点击追加或取消单个；Shift 点击选择当前显示树顺序中的范围。
- Shift 范围可以跨文件夹；文件夹行可选择。折叠文件夹的隐藏后代仍参与选择器中的范围计算。
- 选择单个 PSD 子图层时只导入该图层。当前选中的是 Layout 时导入到该 Layout；当前选中的是非 Layout 节点时忽略该选择并导入根固定 Layout。
- 导入文件夹时创建 `Layout`，递归导入已勾选后代；即使没有成功导入子项，明确选择的文件夹仍保留为空 Layout。
- PSD `root` 下的文件夹默认转换为 Layout；资源绑定不自动执行，用户在资源绑定工作区中手动确认。资源绑定卡片按容器边界拆分：父 Layout 与嵌套 Layout、List、ListHorizontal、GridView 分别作为独立层级范围展示；容器内部的图片不显示在外层卡片中。
- 导入到已有 Layout 时，将世界坐标转换为目标 Layout 的局部坐标，保持画面位置、尺寸和内部相对关系不变；已有空 Layout 自动扩展以包含新内容。
- 普通 Layout 的尺寸按全部子节点的视觉包围盒重新计算，位置保持不变；空 Layout 尺寸为 0×0，在画布上不可见但可以在层级树选中和继续添加子节点。
- 最顶层固定 Layout 尺寸始终等于设计画布，不自动扩展；超出画布的导入内容保留其位置并自然裁剪。
- 导入成功后自动选中新节点；导入文件夹时选中新建 Layout；批量图片自动多选新节点。
- 大型 PSD 或批量导入显示进度并支持取消；取消保留已经成功导入的内容，未处理项不导入并统一显示结果。
- 单个文件复制失败不回滚其他成功项；失败项跳过并汇总原因，只要有成功项就将工程标记为已修改。

### 4. 外部图片导入与资源去重

- 支持 PNG、JPG、JPEG、WebP、BMP、GIF 第一帧；PSD/PSB 使用图层选择器；SVG 栅格化为 PNG。
- 从菜单或桌面拖入的图片复制到工程 `.assets`，不保留外部路径依赖。
- 拖到层级树时导入到当前选中的 Layout；没有选中 Layout 时导入根固定 Layout。
- 拖到画布时以上述目标规则插入，图片中心对齐鼠标位置，保留原始像素尺寸。
- 批量图片成为同级节点；第一张位于鼠标位置，后续图片以小偏移错开，避免完全重叠。
- 图片统一进行有效像素裁切：以 alpha 大于 0 的最小包围盒为有效区域；全透明图片提示并跳过。
- 裁切后以无损 PNG 保存到 `.assets`，并调整节点位置、尺寸和锚点，使画面视觉效果与裁切前一致。
- PSD 图层和外部图片均遵循相同的裁切、资源保存和视觉保持规则。
- 资源文件名由图层名或原文件名生成；Windows 非法字符被清理，名称尽量可读，冲突时添加编号。
- F2 只修改 UI 节点名称，不修改资源文件名。
- 只有内容完全相同且尺寸完全相同的图片才去重；同一视觉内容的不同尺寸保存为不同资源。
- 同内容资源在工程中只保留一份，但每次导入仍创建独立 UI 节点。
- 同名不同内容自动添加后缀并提示，不覆盖已有资源。
- 删除 UI 节点不自动删除资源；资源清理单独执行。

### 5. PSD 图层类型与效果

- 普通 PSD 图片默认导入为 `StaticImage`。
- 文字图层默认导入为可编辑 `StaticText`，文字内容、字体、字号、颜色、对齐、换行、描边、投影及可保存的文字属性写入工程。
- 阴影、描边、蒙版、矢量、智能对象等复杂视觉效果，如果无法可靠映射为编辑器属性，则合成为最终可见效果 PNG，裁切有效像素后保存到 `.assets`。
- 不因 PSD 后续修改而重新生成上述资源；工程内 PNG 是导入时的独立快照。
- 默认保留 PSD 导入时的可见性、透明度、位置、尺寸和旋转；导入后由 UI 工程完全管理。

### 6. 层级、选择与控件类型

- 固定根节点不可删除、不可改类型；PSD 内容导入其下方。
- 层级面板只负责层级管理、选择、展开折叠、显隐、锁定和控件类型图标展示，不提供控件类型切换下拉框。
- 控件类型在 Inspector 中指定，也可以对单选节点按 T 打开类型转换饼菜单；转换结果实时更新层级图标并保存。
- 层级面板图标使用统一颜色体系；面板宽度约 220–480 像素可拖动调整，边界显示双向调整光标；长名称省略显示并通过悬停查看完整名称。
- UI 层级树支持普通单选、Ctrl/⌘ 加选/减选、Shift 连选。Shift 锚点是最近一次普通点击，Ctrl/⌘ 点击不改变锚点；折叠 Layout 的后代仍参加 UI 树范围计算。
- 画布使用普通点击；复杂多选通过层级面板完成。
- 在 UI 层级树中点击 Layout 只选中 Layout 本身，不自动选中后代。
- Ctrl+G 对单个或多个节点创建新的 Layout 包装层；跨父级时放在最近共同父级下；禁止同时选择父节点和其后代打组。
- 打组后保持节点画面位置、相对顺序和已有配置，并选中新建 Layout。
- Alt+G 对单选分组节点取消打组；子节点释放回原父级，保持位置、顺序和配置，成功后选中第一个释放节点；对非分组节点直接无反应。
- Ctrl+[ / Ctrl+] 按 Photoshop 规则调整前后层级顺序。向相邻 Layout 或列表容器移动时进入该容器；到当前文件夹边界后允许跨出文件夹成为同级节点，但不能离开最顶层固定 Layout；多选时整体移动并保持相对顺序。
- F2 对单选节点在层级树原位打开重命名输入框；Enter 或失焦确认，Esc 取消；输入框、文本域和下拉框获得焦点时，快捷键不拦截正常输入。
- 用户通过 Inspector 或 `T` 饼菜单手动切换控件类型时，只替换名称中的类型前缀，保留 AI、本地规则或用户已经确定的语义后缀；类型转换不重新调用 AI，也不自动进入 F2。固定根 Layout 和清除类型标记不触发重命名。
- 控件名称前缀固定使用小写英文缩写：`Layout=layout_`、`Button=btn_`、`CheckBox=chk_`、`RadioButton=radio_`、`Edit=edit_`、`StaticImage=img_`、`StaticText=txt_`、`ProgressBar=pbar_`、`Slider=slider_`、`List=vlist_`、`ListHorizontal=hlist_`、`GridView=grid_`；`empty` 和没有专用缩写的未来类型使用 `node_`。AI 导入命名与手动类型转换共用同一份前缀映射。
- 优先使用工程中保存的 `naming.suffix`；旧工程缺少该数据时，从已有标准前缀或旧版前缀中提取后缀。无法得到后缀时只生成目标类型前缀。相同父节点发生重名时在完整名称后使用最小可用编号，例如 `grid_inventory_2`；不同父节点允许重名。
- F2 仅由用户主动触发，用于手动修改完整名称；F2 保存的后缀在后续类型转换中继续保留。
- 类型转换与前缀替换合并为一个撤销操作；在 `List`、`ListHorizontal` 和 `GridView` 之间切换时同样只替换前缀。
- T 只对单个可编辑节点打开饼菜单；多选、无选择、锁定节点和固定根节点不响应。
- 饼菜单出现在最近一次鼠标位置，靠近边缘时自动避让；显示图标、名称和当前类型高亮；点击普通类型立即转换并关闭，点击外部或 Esc 关闭且不修改。
- T 饼菜单按相似度分成四个方向的分类卡片：左侧为进度/滚动类（`ProgressBar`、`Slider`），上侧为容器/布局类（`Layout`、`empty`、列表容器），右侧为交互类（`Button`、`CheckBox`、`RadioButton`、`Edit`），下侧为内容展示类（`StaticImage`、`StaticText`）。
- 点击“列表容器”后在原菜单位置进入第二级排列方式菜单，提供“纵向列表”“横向列表”“网格列表”，分别直接写入最终类型 `List`、`ListHorizontal`、`GridView`；不创建或保存中间的通用列表类型。第二级菜单高亮当前排列方式，支持返回；点击外部或 Esc 取消整次选择且不修改节点。
- 分类卡片显示分类标题，卡片内使用两列小网格；控件顺序按上述列表固定，容器类超过一行时自动换行。四个方向的布局保持稳定，菜单靠近屏幕边缘时整体避让，不翻转方向。
- 中心区域继续显示当前控件类型图标和名称；鼠标悬停某个类型时，中心临时显示待切换类型。其他未明确的饼菜单细节暂不扩展。
- 类型转换清理与目标类型不兼容的属性，并保留可兼容属性；转换不因节点存在子节点而被禁止，因为自研引擎允许控件节点包含子节点。
- Layout 转换为 `ProgressBar` 或 `Slider` 时创建默认进度配置：值为 `0`，宽度大于等于高度时为水平方向，否则为垂直方向，反向关闭；离开这两种类型时清理进度配置。
- 图片转 Layout 时自动创建图片子节点，原图片视觉不丢失；Layout 转资源控件时子节点继续保留，可通过 Ctrl+B 绑定资源槽位。

### 7. 控件、底图与绑定

- 支持识别的类型包括 `Layout`、`StaticImage`、`StaticText`、`Button`、`CheckBox`、`RadioButton`、`ProgressBar`、`Slider`、`Edit`、`List`、`ListHorizontal`、`GridView`、`DefaultWindow`、`ActorWindow`、`DynamicImage`、`UrlImage`、`SceneImage`、`SlotTable` 和 `EffectViewOfObtainment`。
- 第一版优先完整编辑和导出 `Layout`、`StaticImage`、`StaticText`、`Button`、`CheckBox`、`RadioButton`、`ProgressBar`、`Slider`、`Edit`、`List`、`ListHorizontal` 和 `GridView`；专有类型先保留类型并提示未完成字段。
- `CheckBox` 和 `RadioButton` 至少支持 `Area`、`NormalImage`、`PushedImage`；编辑器另保存可选的初始勾选/初始选中状态，用于画布预览。该状态只属于 `.ui.json` 工程数据，导出自研引擎 JSON 时忽略，不提示、不阻止导出；运行时状态仍由业务代码控制。可选文本、字体、描边、文本偏移、对齐和九宫格。
- `ProgressBar`/`Slider` 支持背景、进度、滑块头、方向、快速滑动和进度值等字段。
- `ProgressBar`/`Slider` 属性面板显示进度值、方向和反向；进度值通过带上下限的拖动数值行调整，拖动和直接输入都限制在 `0..1` 并四舍五入到两位小数。编辑器画布不直接拖动改变这两个控件的进度值。
- `Edit` 支持文本、字体、颜色、对齐、背景图和最大文本长度等字段；属性面板必须提供“输入框文本”，内容可在画布预览并保存到 `.ui.json`。
- 文字控件工程属性至少包括 `Text`、`Font`、`TextColor`、`TextHorzAlignment`、`TextVertAlignment`、`TextWordWrap`、`TextSelfAdaptHigh`、`TextShadow`、`TextShadowColor`、`TextBorder`、`TextBorderColor`、`TextScale`、`TextLineExtraSpace` 和 `TextAutoOmission`。UI2HTML 预览对描边和投影提供近似显示；引擎不支持的描边粗细、投影距离等细节只保留编辑器数据并在导出时给出警告，不把文字栅格化。
- 新导入或新建的文字默认使用引擎兼容字体，水平和垂直文本对齐默认均为居中。PSD 已明确写入且属于引擎支持范围的字段，即使用户没有在 UI2HTML 中重新设置，也必须保留并导出；因此工程需要记录字段是否来自导入源或被用户显式设置，不能仅用“是否等于默认值”判断是否导出。
- `LayoutBackImage` 只表示 Layout 背景；可移动可排序的图片使用 `StaticImage.ImageName`；按钮、进度条、滑动条和编辑框使用各自资源槽位。
- 编辑器预览必须绘制所有已实现控件的可见资源槽位：交互控件默认显示普通状态图（缺失时回退到按下状态图），进度条和滑动条按背景、进度、头部的顺序叠加显示。
- `ProgressBackImage` 始终适配控件矩形；`ProgressImage` 先适配轨道区域，再依据有效进度范围裁切，进度为 `0` 时完全不绘制。水平默认从左到右，垂直默认从下到上；开启反向后分别改为右到左和上到下。
- `ProgressHeaderImage` 是特殊资源槽位：以绑定前图片节点的当前视觉尺寸为准并保持原比例，不随控件整体尺寸缩放；滑块头中心沿方向从控件轨道起点移动到终点，允许在两端向外扩展半个自身尺寸。存在进度图片时，进度图片从轨道边缘开始，其末端与滑块头中心同步；隐藏滑块头时仍使用同一轨道边缘到进度边缘的裁切范围。
- PSD 底图默认作为普通 `StaticImage` 导入；用户在资源绑定工作区选择图片后，手动绑定到 `LayoutBackImage`，解除绑定可恢复普通图片节点。
- Ctrl+B 只接受图片节点，按层级树选择顺序将图片绑定到共同的最近可绑定控件祖先的空资源槽位；包含非图片节点、没有共同控件或目标槽位已满时不修改并提示原因。
- 当目标控件槽位已全部填充但仍有图片节点时，再次 Ctrl+B 将该控件标记为“资源绑定完成”；该确认状态保存到 `.ui.json`，未绑定图片仍保留以便回看，解除绑定会清除确认状态。
- Ctrl+B 的语义按选择内容区分并在界面中直接提示：选中 `StaticImage` 始终表示“将图片绑定到最近可绑定父控件”，不能触发确认完成；只选中一个非 `StaticImage` 的可绑定控件表示“确认完成”（即使槽位留空）；已确认卡片可执行“恢复待处理”。
- 槽位顺序只用于资源绑定工作区的展示，不作为自动绑定依据；用户可以按图片选择顺序或指定目标槽位完成绑定。
- 绑定图片移动到资源槽位后不再作为普通子节点；解除绑定恢复为普通图片节点。绑定与解除绑定均可撤销并保存。
- 资源绑定工作区按“仍有待处理图片优先、图片已处理完靠后”动态排序；卡片底色区分两种状态，同一状态内保持原层级顺序。资源槽位允许按实际需求留空。
- 资源绑定工作区顶部显示“已完成控件数/可绑定控件总数”（例如 `22/23`），下方进度条与该计数同步。
- 每张绑定卡片显示控件在当前预览视口中的有效范围预览（应用父级裁切和视口裁切），点击预览直接定位层级并同步右侧总览。
- 资源绑定工作区右侧显示场景总览：绘制当前完整预览视口，并用红色虚线框标记当前节点有效范围；点击总览中的节点或红框也执行定位。
- 定位操作自动展开并滚动层级树，使目标节点进入明显视野；总览和卡片只负责定位与确认，不改变绑定数据。
- `List`、`ListHorizontal` 和 `GridView` 在工程及导出中始终是三个明确类型，仅在 T 饼菜单中归入同一个“列表容器”入口；单个或多个节点可包装成 item 模板。

#### 7.1 列表 item 预览

- 列表属性面板增加“预览 item”和“重复数量”。item 只能从该列表的直接子节点中手动选择一个节点作为模板；不允许选择后代节点或其他列表节点。
- item 重复是纯预览实例，不新增层级节点、不产生新的稳定 ID、不参与选择、绑定、保存为独立节点或自研引擎 JSON 导出。工程只保存 item 的稳定 ID 和重复数量。
- 指定 item 后，预览中以该节点的完整子树作为重复内容；其他直接子节点默认作为列表装饰保留，若与 item 同属重复候选则隐藏，避免重复显示。未指定 item 时，列表按真实子节点正常排版。
- 重复实例沿用列表类型的排列规则、间距、内边距和当前适配结果；超出列表容器范围的实例裁切，不改变真实层级和导出结构。
- PSD 导入或列表首次创建时，如果列表尺寸等于唯一 item 的尺寸或没有明确设置过尺寸，列表标记为“尺寸待确认”。属性面板显示提示和“确认当前尺寸”操作；用户直接修改宽度或高度，或点击确认后，清除待确认状态并将当前尺寸视为列表容器尺寸。
- “尺寸待确认”只影响编辑器提示和预览，不阻止保存；导出校验可以将其作为警告，不自动改变列表大小。

### 8. 资源面板与外部资源变化

- 资源面板展示 `.assets` 中全部资源，按资源文件名自然顺序排序，不提供搜索和筛选。
- 每项显示缩略图、文件名和尺寸；点击只预览，不显示引用次数或引用关系。
- 资源面板支持资源重命名、替换和清理未使用资源；重命名资源文件并同步全部 JSON 引用，UI 节点名称不变。
- 资源重命名发生冲突时禁止执行且提示，不覆盖文件。
- 删除被引用资源时禁止执行，并显示引用节点/槽位；删除和清理支持当前会话撤销，关闭工程后不迁移历史。
- 替换共享资源会更新所有引用，节点位置、视觉/交互尺寸和控件属性不变；替换采用有效像素裁切和无损 PNG 规则。
- 资源替换直接执行，不显示替换前后对比；支持当前会话撤销。
- 外部资源被替换或删除时提示用户；确认替换则重新加载内容，删除则使用占位显示但保留节点和 JSON，不自动搜索 PSD。
- 外部替换仅改变图片内容；即使尺寸变化也保留节点位置、视觉/交互尺寸、交互属性和控件属性。
- 清理未使用资源时扫描普通节点、隐藏节点、资源槽位和已确认的九宫格公共源图；动画资源管理留待后续版本。

### 9. 视觉布局与校正

- PSD 导入和工程预览统一使用设计画布左上角为 `(0,0)`，向右为 `X+`，向下为 `Y+`。
- `designRect` 保存节点在设计画布中的当前解析视觉矩形，供编辑器保持 PSD 初始效果和进行预览；位置/尺寸的表达方式另由每个字段的布局项保存。
- 位置和尺寸允许直接微调，定位为“视觉校正”，不提供完整锚点驱动或响应式布局编辑。
- 打组、取消打组和换父级必须保持当前视觉位置、尺寸和相对顺序；只更新节点当前层级及其局部坐标。
- 属性面板保留 `Parent Anchor` 与 `Self Anchor` 的旧九宫格操作：`Parent Anchor` 映射为引擎的 `HorizontalAlignment`、`VerticalAlignment`，`Self Anchor` 指定控件自身锚点；切换时保持当前视觉位置。
- 节点的 X、Y、宽、高四个字段各自支持“绝对 / 相对”二选一，面板不要求用户同时编辑两种值。绝对值是设计像素偏移或尺寸，相对值是相对父节点宽/高的比例；相对值显示为可拖动的小数并保留两位小数。未选择相对模式的字段保持现有绝对值逻辑，旧工程默认全部为绝对模式。
- 内部布局项仍保留引擎所需的 `relative` 与 `absolute` 两部分，解析值统一按“父节点尺寸 × relative + absolute”计算。UI 面板选择某一模式时，另一部分被归零或标记为未设置，避免出现“相对值已换算但又叠加原绝对值”的视觉翻倍问题。相对值转换示例：父节点为 `2000×1000`、子节点当前视觉尺寸为 `1280×720`，转为纯相对尺寸后保存 `0.64,0.72` 和 `0,0` 绝对偏移，当前设计画面仍保持 `1280×720`；不能保存为 `0.64,0.72` 同时叠加 `1280,720`。
- 位置的相对转换必须以当前 `Parent Anchor`、`Self Anchor` 和引擎 Area 语义计算，不能简单对画布坐标做除法；转换完成后当前设计视口的视觉位置保持不变。普通节点以父节点为参照，一级节点以设计画布/根布局为参照。
- 打开包含引擎混合值的旧工程时，面板显示“引擎混合值，仅保留”并保持只读，不擅自改写；用户明确选择绝对或相对模式后才将该字段规范化为单一表达。未编辑、直接保存时保留原混合值。
- `adaptation.mode` 只负责 UI2HTML 的预览辅助：`anchor` 使用节点布局数据，`scale` 不作为用户可见的节点适配选项，历史值仅兼容读取，`stretch` 表示填充父节点。它们不直接作为同名字段导出到引擎 JSON。
- 根节点是特殊的全视口节点：PSD 尺寸仍作为设计画布尺寸，根节点的相对宽高固定为 `1,1`、绝对宽高为 `0,0`。切换设备或自定义分辨率时，根节点跟随视口变化；根节点不绑定安全区，安全区只用于子节点适配检查。
- `stretch` 节点导出时转换为父节点范围的 `Area`；它不转换为引擎 `StretchType`。引擎 `StretchType` 只表示图片的纹理拉伸方式，例如 `NineGrid` 和 `RepeatFill`。
- 设备预览支持常见设备比例、自定义视口宽高、缩放模式、安全区和设计边框；这些设置只改变检查画布，不能替代节点布局或引擎适配字段。
- 动画仍不作为当前版本工程编辑能力；九宫格作为独立工作区的图片处理和预览能力，不进入普通属性面板。

### 10. 自研引擎 JSON 导出

- 工程 `.ui.json` 始终引用工程 `.assets` 中的独立图片；最终引擎 JSON 通过独立适配层输出可追溯的工程资源引用。
- 正式导出会将工程图片打包为引擎兼容的 imageset，图片字段统一使用 `set:<工程名>.json image:<frame>`，不再把 `.assets` 相对路径直接写入引擎 JSON。
- 已确认九宫格的节点/资源槽位在正式导出时改用 `.assets/9` 的公共源图，并在同一个引擎 Window 上输出 `StretchType=NineGrid` 与 `StretchOffset=左 上 右 下`；未确认的九宫格仍使用原图和普通显示。
- 九宫格和图集的多图集增量维护、间隔、出血与生产打包规则留待后续独立模块。
- 当前正式导出阶段只生成一个自包含测试 imageset；除场景级背景的 50% 导出缩小规则外，通用图片缩放、旋转、多图集归属和生产环境图集策略仍留待后续独立模块。背景图在引擎 JSON 中仍使用原设计 Area，依靠引擎按控件范围采样拉伸，保持视觉尺寸不变。
- 导出结构为 `Dialog → Window`，每个节点导出 `Type`、`Name`、`Property` 和可选的子 `Window`。
- 每个节点的 `Area` 使用引擎的左上/右下坐标语义：`{{xMin},{yMin},{xMax},{yMax}}`，不是 `x/y/width/height`；每个坐标由“相对值 × 父节点尺寸 + 绝对偏移”组成，对齐节点只换算一次相对父容器的偏移。UI2HTML 面板的绝对/相对二选一只影响编辑器写入的规范化结果，不改变引擎支持的混合 Area 能力。根节点导出为 `{{0,0},{0,0},{1,0},{1,0}}`。
- 图片槽位按控件类型映射到引擎字段；资源缺失、名称缺失或槽位引用失效时阻止导出并提示。
- 文字字体统一输出 `HT8…HT160` 的引擎预设；编辑器专用字体、选中状态等字段不导出。导出前校验节点类型、名称、Area、资源引用和必需槽位；未实现的专有字段以警告提示。
- 导出页提供“引擎测试包输出目录”设置。生成的包包含 `res/layout/<工程名>.json`、`res/imageset/<工程名>.json`、`res/imageset/<工程名>.png` 和 `README.txt`；输出目录由使用者填写，不写入真实引擎工程。
- “下载最终 JSON”适合查看或交付单文件；“生成引擎测试包”适合用引擎 UIEditor 验证。由于引擎 UIEditor 只从已登记的资源目录加载，使用者需将测试包内的 `res/layout` 与 `res/imageset` 复制到目标引擎游戏对应目录后再打开。

### 11. 引擎 UIEditor 资源加载验证结论（2026-09-09）

- 引擎 UIEditor 的文件选择框允许选择任意路径，但打开 JSON 时，内部会取所选文件的纯文件名，再交给引擎资源管理器按资源名加载；因此桌面或其他未登记目录中的 JSON，即使在文件选择框中选中，也可能被打开成空白。
- 引擎 JSON 必须放在当前 UIEditor 已登记的 `res/layout` 资源目录中；JSON 引用的 imageset JSON 和 PNG 必须放在同一运行配置已登记的 `res/imageset` 资源目录中。仅把 JSON 和图集放在同一个桌面文件夹，不足以完成引擎 UIEditor 验证。
- 图集引用必须使用引擎格式 `set:<imageset>.json image:<frame>`，图集描述 JSON 使用引擎实际支持的 `frames`/`meta` 结构；不能直接把 UI2HTML 的独立图片路径写入引擎 JSON。
- 新增或替换 imageset 后应重启引擎 UIEditor，再重新打开 JSON，避免资源位置列表或已加载资源缓存导致误判。
- 当前验证已确认：将测试 JSON 放入启用游戏 `g1048` 的 `res/layout`，将配套图集放入 `g1048` 的 `res/imageset`，引擎 UIEditor 可以正确显示节点和视觉效果。该验证只产生测试资源文件，不修改引擎代码。
- 当前验证中，节点的 `Area`、图片资源、`Text`、`HorizontalAlignment` 和 `VerticalAlignment` 均正确；文字节点仍可能出现视觉位置偏差，优先按字体度量差异排查，不直接判定为坐标转换错误。
- 引擎 UIEditor 的文字 `Font` 属性是预设枚举（例如 `DEFAULT_HT16`、`HT20` 等），不能像 UI2HTML 编辑器一样直接指定字体文件和具体字号。现已确认项目 `GUIResConfig.json` 中的预设使用 `DroidSans.ttf`，字号为 `HT8、HT10、HT12、HT14、HT16、HT18、HT20、HT22、HT24、HT26、HT28、HT30、HT32、HT34、HT36、HT48、HT64、HT72、HT120、HT160`；`DEFAULT_HTn` 与对应 `HTn` 为同字号别名。
- UI2HTML 编辑器默认使用 `DroidSans`（项目内置字体）绘制文本；PSD 导入的文字无论原字体名称是什么，都替换为 `DroidSans`，字号向上取最近的引擎预设字号，以避免字体替换后视觉变小。字号低于 `HT8` 或高于 `HT160` 时限制到边界，并在导出时给出警告；用户仍可通过现有全局字体入口主动覆盖预览字体，但引擎 JSON 始终输出可识别的 `HTn` 预设。
- 文本在 UI2HTML 画布预览、HTML 预览和引擎 JSON 中默认水平、垂直居中；引擎 JSON 对文本节点写入 `TextHorzAlignment=Centre` 与 `TextVertAlignment=Centre`。这两个对齐属性属于文本默认行为，与节点的 `Parent Anchor`（引擎 `HorizontalAlignment/VerticalAlignment`）分开处理。
- `position_test` 实测根节点 `layout_main_screen` 为 `Layout`，`Area={{0,0},{0,0},{0,1280},{0,720}}`，`HorizontalAlignment=Left`、`VerticalAlignment=Top`，`LayoutBackImage=set:position_test.json image:img_gray_background`；与导出结果一致。
- `position_test` 实测图片节点 `img_left_region` 为 `StaticImage`，左上对齐，`Area={{0,33},{0,33},{0,267},{0,131}}`，`ImageName=set:position_test.json image:img_left_region_red`；与导出结果一致，其他通用默认属性无异常。

## Acceptance Criteria

### 工程解耦与保存

- 修改 PSD 后，已保存 `.ui.json` 的节点名称、层级、位置、尺寸、控件类型、绑定和资源内容不发生任何变化。
- 重新打开 `.ui.json` 不读取同名 PSD；工程只依赖自身 JSON 和 `.assets`。
- 保存、另存为、关闭、重新打开和多标签切换均能恢复对应工程的完整快照。
- `.ui.json` 与 `.assets` 保存失败时不产生半成品；旧工程和备份保持可用。
- 撤销/重做历史不写入文件，重新打开后不恢复历史记录。

### 导入

- PSD 选择器默认不勾选，能展示 Photoshop 图层结构并支持普通点击、Ctrl/⌘ 加选/减选和 Shift 连选。
- 一键导入包含隐藏图层和空文件夹；选中导入只提交用户勾选内容，取消无副作用。
- `root` 文件夹生成空 Layout；普通文件夹生成 Layout 并保留导入后的子层级。
- 图片有效像素被裁切为独立 PNG，裁切后画面位置和尺寸视觉不变；全透明图片被跳过并提示。
- 文字图层成为可编辑 `StaticText`；复杂效果成为独立 PNG；两者均不依赖 PSD。
- 文本默认使用引擎 UIEditor 的 `DroidSans` 字体；PSD 原字体不作为工程运行时依赖，导入时统一替换为 `DroidSans`，字号映射到不小于原视觉字号的最近引擎预设值。
- 菜单和拖拽图片支持任意系统路径、批量导入、自动错开、自动选择和失败汇总。
- 导入到 Layout 时保持世界位置；空 Layout 自动扩展，根固定 Layout 不扩展。
- 列表可选择直接子节点作为虚拟 item 并设置重复数量；预览能看到重复排版，但层级树和引擎 JSON 不增加 item 实例。
- 列表初始尺寸未确认时显示明确提示；修改宽高或确认当前尺寸后提示消失，导出只给警告不自动改尺寸。

### 层级与控件

- 层级树的选择、Ctrl+G、Alt+G、Ctrl+[、Ctrl+]、F2 和 T 行为符合规格，并能保存。
- 属性面板保留 Parent/Self Anchor 九宫格；Parent Anchor 导出为 HorizontalAlignment 与 VerticalAlignment，切换对齐不造成画面跳动。
- X、Y、宽、高可以分别在绝对/相对模式间切换；转换前后设计画面的当前视觉位置和尺寸不跳变，UI 不会误把相对值与旧绝对值叠加。
- 设备预览可以切换常见设备尺寸或自定义宽高，并检查完整显示、按宽度、按高度、等比铺满和拉伸铺满效果；安全区与设计边框显示不改变节点数据。
- 单节点 Ctrl+G 可以创建外层 Layout；Alt+G 对非分组节点无变化。
- 跨文件夹层级调整可以成为同级节点，但永远不能移出顶层固定 Layout。
- 类型饼菜单只允许单个可编辑节点打开，支持边缘避让、当前类型高亮、外部点击/ Esc 关闭和即时转换。
- 自研引擎允许控件节点包含子节点，因此具备资源槽位的控件不会因存在子节点而被禁止转换。
- 层级面板图标统一颜色，宽度可拖动，边界显示双向光标，长名称和深层级可读。
- Slider/ProgressBar 的进度属性、方向、反向、资源尺寸策略、进度起点和滑块头越界渲染边界符合上述规则；类型转换、保存重开后这些配置保持不变。
- 手动类型转换只替换前缀并保留语义后缀，不调用 AI、不自动进入 F2；列表容器二级菜单、三个最终引擎类型、同父级重名避让和单次撤销行为符合规格。
- Ctrl+S 会打开左右分区的快捷操作面板：左侧为新建、打开工程、导入 PSD、导入图片，右侧为保存、另存为、关闭当前工程；选项执行正确，关闭工程沿用未保存修改确认，Esc/点击外部可关闭且不产生操作。
- Ctrl+B 按选择顺序绑定图片资源槽位，绑定与解除绑定结果可保存并恢复。

### 资源与导出

- 资源面板按自然文件名展示全部资源，可预览、重命名、替换和清理；不显示引用次数、搜索框或筛选器。
- 同内容同尺寸资源去重；不同尺寸或不同内容不错误合并；资源命名冲突不覆盖旧文件。
- 被引用资源不可直接删除；替换和重命名同步全部引用，且不改变节点布局和控件属性。
- `.ui.json` 只引用独立图片，最终引擎 JSON 映射到导出包中的 imageset frame，二者通过资源清单和回归测试相互校验。
- 九宫格工程数据、候选状态、逻辑图片组、公共源图和四个边距能够保存并重新打开恢复；已确认的组不会因重新扫描被覆盖。
- 预览工作区可以在整张画布范围切换原图和已确认的九宫格显示，并与设备比例、安全区和设备外壳预览共同工作。
- 文本导出使用 `HTn` 引擎字体预设，并写入 `TextHorzAlignment=Centre`、`TextVertAlignment=Centre`；编辑器画布和 HTML 预览也采用相同的水平/垂直居中规则。PSD 或工程中已明确设置的其他引擎支持字段也必须导出，即使其值恰好等于默认值。
- 列表虚拟 item 和重复数量只用于 UI2HTML 预览，导出校验和引擎 JSON 均忽略这两项。
- 已完成的九宫格结果直接复用原图标记阶段的四条边距；导出使用 `.assets/9` 生成图、`StretchType=NineGrid` 和 `StretchOffset`，不增加第三阶段确认步骤。
- 工具栏提供项目字体下拉框和相邻的循环切换按钮；选择下拉项立即将字体应用到全部文本，不需要回车确认；循环切换按字体列表顺序前进并从末项回到首项。
- 导出 JSON 结构、节点类型、Area、图片槽位和资源引用正确；导出校验失败时不生成正式结果。
- 九宫格使用独立工作区；布局适配和动画不出现在当前版本工作区，后续可独立增加。

## Testing Decisions

- 以用户可观察行为为测试目标，不测试 React 组件拆分、临时状态变量或内部实现细节。
- 最高测试 seam 为“外部素材/PSD 导入 → 工程编辑 → 保存重开 → 自研引擎 JSON 导出”的完整流程。
- 使用 PSD fixture 覆盖 root 文件夹、嵌套文件夹、空文件夹、隐藏图层、普通图片、文字、透明边界和复杂效果。
- 使用独立 `.ui.json` 与 `.assets` fixture 验证保存、另存为、重复打开、多标签、外部文件变化和缺失资源占位。
- 使用导入后修改 PSD 的 fixture，确认工程重开结果完全不受 PSD 后续变化影响。
- 使用层级交互测试验证统一选择规则、跨文件夹 Shift 范围、Layout 单独选择、打组、取消打组、跨文件夹调整顺序、F2、T 饼菜单及列表容器二级排列方式菜单。
- 使用列表 fixture 验证直接子节点 item、虚拟重复数量、列表裁切、尺寸待确认提示，以及 item 数据不进入层级和引擎导出。
- 使用相对布局 fixture 验证绝对/相对二选一、相对值换算、混合引擎值只读保留、切换表示方式不改变设计视觉结果，以及根节点随预览视口变化。
- 使用控件字段 fixture 验证 `ccc.json` 参考的主要控件、底图槽位、资源绑定和类型转换。
- 使用 Slider/ProgressBar fixture 验证类型转换默认配置、进度值约束与两位小数、方向/反向、进度图片裁切、进度为 0 隐藏、滑块头保持原始视觉尺寸，以及资源绑定后保存重开。
- 使用文字 fixture 验证引擎字体映射、默认水平/垂直居中、引擎文字属性保存与导出，以及不支持的描边粗细/投影距离仅警告不栅格化。
- 使用九宫格 fixture 验证三阶段工作区、图片多选归组、最大源图、原图标记与自适应压缩、结果页沿用边距且无二次确认、重新标记后结果更新，以及引擎 `NineGrid`/`StretchOffset` 导出。
- 使用资源 fixture 验证有效像素裁切、透明图片跳过、同内容去重、不同尺寸分离、重命名、替换、删除保护、清理和撤销。
- 使用失败 fixture 验证导入部分成功、取消、保存事务、导出事务、备份和错误提示。
- 优先复用现有场景持久化和导出测试入口；如果没有浏览器端测试基础设施，再增加一个覆盖完整用户流程的端到端入口。

## Out of Scope

- 不修改 PSD，不把 UI 工程结果写回 Photoshop。
- 不做 PSD 与工程的自动同步、差异更新、自动重新关联或 PSD 监听。
- 不在工程中保存 PSD 路径、PSD 图层 ID 或自动更新元数据。
- 不做真实业务数据绑定；列表第一版只提供 item 模板、占位数据和预览数量。
- 不做自研引擎运行时、Lua 驱动或引擎加载器改造。
- 不做生产环境图集优化、用户可配置图集尺寸、图片旋转、边缘像素扩展或有损压缩；当前导出只生成用于引擎 UIEditor 验证的基础 imageset。
- 不做九宫格图集的生产级多图集优化；当前只导出已确认九宫格的 `.assets/9` 公共源图，并输出引擎 `NineGrid`/`StretchOffset` 字段。
- 不做完整响应式布局编辑器、复杂约束布局或动画编辑器；保留 Parent/Self Anchor 的引擎字段设置，并支持明确的相对宽高配置。
- 不默认或可选生成 ZIP。
- 不提供素材引用关系浏览、引用次数显示、搜索或筛选功能；删除保护和清理扫描仍然必须识别引用。
- 不把撤销/重做历史迁移到工程文件。
- 未确认的专有控件字段只保留类型、已有通用数据和提示，不承诺完整编辑能力。

## Further Notes

- 本规格取代早期“打开 PSD 后持续更新同名工程”和“通过 PSD 图层 ID 重新挂载资源”的设计。
- 旧的同名普通 JSON 不迁移、不自动处理，不承担历史兼容负担；新工程统一使用 `.ui.json`。
- 控件节点包含子节点在自研引擎中允许存在，不再以“非法节点”限制类型转换或资源绑定；具体引擎字段校验由导出校验负责。
- 最终引擎 JSON 的专有字段继续由适配层隔离；通用 `Area`、图片槽位、`set:... image:...` 图集引用和字体预设已按真实引擎样例固定，并由 `position_test` 回归验证。
- 本地规格已经完成更新。由于当前没有配置 issue tracker 地址、字段和 `ready-for-agent` 标签，暂不发布到外部 issue tracker。
