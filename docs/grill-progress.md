# UI Editor 方案追问进度

更新时间：2026-09-03

这是针对 `控件类型测试.psd` 整理方案的设计追问记录。下次从**第 147 题**继续。

## 已确认的总体原则

- PSD 只负责提供素材；UI Editor 负责最终 UI 层级、打组、控件类型和资源绑定。
- PSD 中除 `9` 外的文件夹只作为初始临时分组，导入后表现为可编辑的 `Layout`；不再根据文件夹名自动推断控件类型。
- PSD 的 `root` 下如果存在文件夹，默认用对应的空 `Layout` 节点替代；文件夹本身不指定图片、不自动绑定资源，内部图片作为其子节点单独导入。
- 文字图层自动识别为 `StaticText`；其他图片默认识别为 `StaticImage`。
- 固定场景根节点不可删除、不可改类型；PSD 的 `root` 内容放在其下。
- “控件类型”面板改为“层级”面板：只负责游戏引擎式的层级整理、选择、展开/折叠、显隐和锁定，并显示当前控件类型图标；不在树内切换类型。
- 控件类型统一在选中节点后的右侧 Inspector 中指定；指定后立即刷新层级图标，并随 `.ui.json` 保存。
- `Ctrl+G` 打组、`Alt+G` 取消打组、`T` 打开类型转换饼菜单；具体交互规则见下方第 127～146 题。
- `F2` 重命名当前单选节点，`Ctrl+W` 关闭当前打开的 PSD。
- `Ctrl+G` 默认创建 `Layout`；一个或多个节点均可打组，单选时创建外层 Layout 包裹该节点；跨父节点打组时，在最近共同父节点下创建新 Layout，并保持画面位置不变。
- 取消打组会保留子节点、顺序和画面位置；`ItemTemplate` 取消后变为 List 普通子节点。
- 拖动换父级、画布多选移动时保持画面位置；父节点和子节点同时选中时只移动父节点一次。
- 调整父节点视觉尺寸默认不缩放子节点；需要整体缩放时使用独立操作。

## 尺寸与资源

- 所有可交互控件区分“视觉尺寸”和“交互尺寸”。
- 交互尺寸默认跟随视觉尺寸；用户手动修改后进入独立模式，可恢复跟随。
- 交互尺寸只影响命中，不影响布局、渲染和子节点位置。
- 绑定资源时，图片默认按用户选择顺序填入槽位。
- 图片默认都是普通 UI 节点；只有主动绑定后才从 UI 层级移到资源槽位。
- 绑定后的图片可通过“解除绑定”一步恢复为原来的普通图片节点。
- 一张 PSD 图片默认只能绑定一个资源槽位；暂不支持多处复用引用。
- 自动绑定：多选未绑定的图片后，绑定到它们共同的最近可绑定控件祖先。
- 视觉尺寸改变后，资源按适配方式显示：拉伸、等比适配或原始尺寸；九宫格资源按九宫格规则显示。
- 资源槽位在界面中用通用名称，同时显示引擎字段名，例如“普通状态（NormalImage）”。
- 第一版实现已确认控件的资源槽位：Button、CheckBox、RadioButton、ProgressBar、Slider、Edit、Layout、StaticImage、List；其他控件按普通子节点处理并提示。
- 其他已支持的控件可以标记和整理，但未确认的专属资源字段不阻塞导出，按普通子节点导出并给出提示。

## 列表

- 编辑器只提供一个“列表”控件，通过排列方式区分纵向、横向和网格；导出时映射到引擎的 `List`、`ListHorizontal`、`GridView`。
- 不再使用 `listitem` 控件类型。
- 用户多选节点后执行“设为列表项模板”，编辑器自动创建逻辑 `ItemTemplate` 容器。
- List 可以有一个背景角色和一个 `ItemTemplate` 角色；角色不是控件类型。
- `9` 文件夹继续作为九宫格候选素材库；同名图片只作为替换建议，最终绑定由 UI Editor 决定。
- 列表第一版支持占位数据和可调整预览数量，不做真实业务数据绑定。

## 文字

- 默认文字、带描边文字、带投影文字都作为 `StaticText`。
- `StaticText` 需要支持描边和投影属性。
- 含外发光、内发光、斜面浮雕、渐变文字、文字变形等暂不支持效果的文字，默认按 `StaticImage` 导入并提示。
- Button.Text 只能绑定一张文字图层；多余文字继续作为普通 `StaticText` 子节点。

## 工程文件与更新

- 每个 PSD 对应同名 UI 工程文件：`控件类型测试.psd` + `控件类型测试.ui.json`。
- `.ui.json` 保存完整的 UI 层级、控件、尺寸、资源绑定、列表角色和 PSD 来源信息。
- `.ui.json` 的节点锚点和控件配置使用稳定 PSD 图层 ID 作为键，不再使用节点名称；旧版按名称保存的配置仅对唯一名称节点兼容读取，重名节点跳过旧配置。
- PSD 更新时不改变已经整理好的 UI；原有图层内容更新只替换素材，新图进入“未使用素材”，删除/无法匹配的图层提示资源丢失。
- 旧的控件命名自动推断不再使用；保存后的 `.ui.json` 以编辑器结果为准。
- 删除 UI 节点只影响当前 `.ui.json`；绑定资源回到未使用素材，PSD 原文件不被修改。

## 引擎样例补充（2026-09-03）

### `ccc.json` 已确认的控件核心字段

- `CheckBox`：`Area`、`NormalImage`、`PushedImage`。
- `RadioButton`：`Area`、`NormalImage`、`PushedImage`；真实样例还使用 `StretchType`、`StretchOffset`、`TextBorder`、`TextRenderOffset`。
- `ProgressBar`：`Area`、`StretchType`、`StretchOffset`、`ProgressImage`；可选 `ProgressBackImage`、`ProgressHeaderImage`。
- `Slider`：在进度条字段基础上增加 `ProgressIsVertical`、`QuickSlide`，并使用 `Progress` 保存预览值。
- `Edit`：`Area`、`Text`、`TextVertAlignment`、`EditBackImage`；真实样例还使用最小/最大宽高、`MaxTextLength`、字体、颜色、对齐和文本偏移等字段。

### 当前可识别的引擎控件类型

在 `g1008/res/layout` 中实际发现：`Layout`、`StaticImage`、`StaticText`、`Button`、`CheckBox`、`RadioButton`、`ProgressBar`、`Slider`、`Edit`、`List`、`ListHorizontal`、`GridView`、`DefaultWindow`、`ActorWindow`、`DynamicImage`、`UrlImage`、`SceneImage`、`SlotTable`、`EffectViewOfObtainment`。

其中 `ActorWindow`、`SlotTable`、`EffectViewOfObtainment` 等属于特殊控件，暂不纳入第一版通用控件属性编辑，但应作为“已识别、字段待确认”类型保留。

### 底图字段结论与建议

真实布局中存在两种底图表达：

- `Layout` 的布局背景使用 `LayoutBackImage`，例如 `AdActivityPanel` 和 `BedWarSettingBasic`。
- 独立图片节点使用 `StaticImage.ImageName`，例如 `ActivityPage-BG`；它可以被单独选中、移动和排序。

因此“底图”不是独立控件类型。建议 UI Editor 默认把 PSD 底图导入为普通 `StaticImage`，只有用户明确执行“设为布局底图”后，才将其绑定到父 `Layout.LayoutBackImage` 槽位并从普通子节点移入资源槽位。`StretchType` 和 `StretchOffset` 保留在承载底图的 `Layout` 或 `StaticImage` 上。

### 图集打包自动推荐决策

以下细节由用户授权自动采用默认方案：

- 113：同一图集内按图片面积从大到小排列，以提高空间利用率；面积相同或无法比较时按稳定标识排序，保证结果可重复。
- 114：只有当前 UI 工程实际引用的资源进入图集；未使用素材不参与图集打包。
- 115：相同图素只在图集中保留一份，所有引用通过图集描述映射到同一资源区域。
- 116：图集打包失败或图集描述生成失败时，导出失败并显示错误摘要。
- 117：图集默认使用无损 PNG，保留透明通道；不使用有损压缩替代源图素。
- 118：图集描述只保存引擎运行所需的图集文件、资源名称、内容区域坐标和尺寸等字段，不额外记录编辑器内部临时信息。
- 119：最终导出的引擎 JSON 文件名由用户在导出时手动指定。
- 120：最终引擎 JSON 包含固定的 `schemaVersion`，用于引擎兼容和后续升级。

### 导出问题自动推荐决策

以下导出细节由用户授权自动采用推荐方案：

- 121：当 `schemaVersion` 高于引擎支持版本时，禁止导出或运行，并明确提示版本不兼容。
- 122：导出前先校验 JSON、资源引用、图集描述和必需字段；校验失败时不写入正式输出目录。
- 123：导出采用临时目录生成全部产物，全部成功后再替换正式输出内容，避免留下半成品。
- 124：导出失败时删除本次临时产物，保留已有 JSON、资源和备份文件。
- 125：最终引擎 JSON、图集描述和资源引用必须互相校验；任一引用不存在都视为错误并禁止导出。
- 126：导出成功弹窗显示输出目录、JSON 文件、资源数量和图集数量，并提供打开输出目录操作。
